# Phase 3 conversion, OCR and compression handoff

## Primary goal

A person can inspect and correct a conversion before saving it, and the saved document retains the supported text, tables, images and page content. OCR and compression act on the same chosen task, explain their limits and preserve a useful original.

This continues the user's full 32-service authorization. It is a coordination handoff, not approval of unimplemented conversion behavior. Read the primary scope and ledger in `02-browserpdf-service-improvements.md`. Phase 2 Highlight/Redact remains active when this handoff is written. Start product work only from the next independently verified actual HEAD supplied by the lead; do not reset to `1184fc6` or overwrite annotation work.

## Ownership and operating rules

Use fresh owners, at most two active workers, without nested agents. The document owner owns shared `pdf-convert.js`, `md-blocks.js`, `md-layout.js`, `md-render.js`, the shared document/Markdown workspace, Word/PDF/Markdown adapters, `docx-writer.js`, shared fonts/text-layout and any narrowly required `tool-ui.js` or loader changes. The second owner requests those shared changes and owns separate compression, standalone OCR and spreadsheet cores/adapters in consecutive small checkpoints. This is a proposed partition; confirm it with the lead before edits. Split a long stream into a fresh successor rather than leaving an indefinitely large unverified rewrite.

Root owns `docs/service-improvements-independent-review.md`, the durable `http://localhost:8788` server and independent native journeys. Never start or stop that server. Every shell command uses `rtk`. Preserve all untracked audit files. Browser/globalSetup invocations require one explicitly allocated exclusive window and frozen public/test source; no concurrent fixture writers. Each report has a unique `/tmp` path and retains failed evidence. No main push, deployment, attribution, new document-upload endpoint or password persistence.

Use the verified composition/session contracts and actual entry-local module URLs. Read `../docs/composition-session-contract.md`, `../docs/shared-composition-checkpoint.md`, `../docs/image-composer-checkpoint.md` and the then-current annotation checkpoint docs. A chosen document's original, provenance, scene, history and typed artifacts must survive deliberate compatible transitions. Resource admission remains transactional and shares the existing joint limits; do not add a disconnected converter store or silently evict history to admit a result.

Read the then-verified `../docs/document-display-name-contract.md` too. Preserve-current transitions carry the authoritative `type` together with the bound `name`/`displayName` pair and capabilities; a 160-character operational filename can have lost its extension and must not be the basis for re-inferring an existing artifact's MIME. A new conversion declares its actual output type and derives its new display label, rather than spreading the source type/label into another format. Full display names remain finite; export names and task/resource limits keep their existing bounds.

### Read-only ZIP discovery for the future owner

The application currently has no bounded ZIP intake contract. `zip-writer.js` only writes stored output. The public native signatures `new DecompressionStream('deflate-raw')`, `writable.getWriter()` and `readable.getReader()` appear in installed PDF.js 6.2.108 (`build/pdf.mjs:25316–25354`); this establishes source-level availability, not browser acceptance of ZIP method-8 payloads. `core/redaction.js:24–49` supplies bounded concurrent read/write, cancellation and final draining patterns, but its zlib-wrapped `'deflate'` format must not be reused unchanged for ZIP raw DEFLATE. A future allocated runtime gate must prove real stored/deflated OOXML parts, CRC/size mismatches, truncation, overflow, cancellation and draining before callers lock that choice.

Installed Pako 1.0.11 documents `new pako.Inflate({raw:true,chunkSize:16384})`, `push(data,false/true)`, `onData`, `onEnd`, `err` and `msg` in its README and `lib/inflate.js`. It is only a transitive development dependency, with no verified browser-loader asset. Its default handlers collect and flatten all output; convenience `inflateRaw` is not an application bound. Treat a deliberately pinned streaming asset as an alternative requiring provenance/loading work if the native feasibility gate fails. Do not assume a `signal` or `maxOutputLength` option, use private Mammoth internals or add an invisible unbounded fallback.

One shared owner should propose a first-party ZIP32 admission/index reader before either converter invokes Mammoth or SheetJS. Validate EOCD/comment/directory bounds, count, safe unique names, matching local headers, methods, nonoverlapping compressed spans, CRC and actual expanded sizes; reject encryption, multidisk, ZIP64 and unsupported methods explicitly. Data descriptors need deliberate validation or an accurate unsupported-state message. Count every entry a downstream library may expand while discarding unwanted output, rather than trusting directory declarations. Retain only required OOXML parts/assets and resolve relationships locally. Copy CRC/header conventions from `zip-writer.js:8–28,35–95`, not its output-only API.

The row/column/cell guards currently run after spreadsheet parsing; they cannot establish ZIP expansion admission. New retained assets and models share existing task/resource/history admission, including the 96-MiB/128-resource and 512-MiB retained-session boundaries; these proposals are not extra capacity and do not promise a hard native/parser heap ceiling. The fresh owner must recheck installed APIs and agree the exact contract on the independently verified post-annotation HEAD. DOCX numbering supplementation needs bounded `word/document.xml`, `word/numbering.xml`, relevant `word/styles.xml` and relationships to preserve `numId`, levels, starts and overrides before Mammoth discards them.

A visible unsaved edit invalidates the preceding review, Download and result-continuation rail immediately, including a callback already waiting on storage. Disabling only workspace mode buttons is insufficient because the result rail has a separate lifetime. Copy the accepted result-generation/owned-operation guards; do not abort a valid current-page preview merely to prepare an unplaced draft, and do not silently save the previous visible value while a new value is pending.

Inspect requested font styles per actual content run. `embedDocumentFonts` currently defaults to embedding regular, bold, italic, bold-italic and code against all text, while Arabic/Hebrew fallback deliberately rejects missing italic/code styles. ### Source-only font and model discovery

A short read-only preflight additionally found that `md-layout.js` already selects used **style names**, but still passes **all runs' text to every selected style**. Filtering names alone therefore does not fix Latin-only italic beside regular Arabic. The future font contract must resolve coverage and requested style for each actual run. `md-layout.js` currently right-aligns a line from a first-character RTL heuristic and then advances pieces left to right; this is not evidence of correct mixed bidi order or contextual line measurement.

The integrity-verified local `@pdf-lib/fontkit` 1.1.1 and installed primary pdf-lib types expose `GlyphRun.glyphs`, `positions`, `direction`, `script` and `language`; positions include advances and offsets (`node_modules/pdf-lib/src/types/fontkit.ts`). The documented installed `Font.layout(str, features?)` type has two arguments; the runtime wrapper's five arguments are not permission to assume additional meanings. Pinned pdf-lib 1.17.1 custom embedders encode returned glyph IDs but measure glyph `advanceWidth`, without consuming returned positions; `PDFPageOptions` exposes no paragraph-direction or positioned-glyph input. Its ToUnicode mapping alone does not prove mixed-direction logical extraction.

An isolated public-API Node probe of the hash-matched Fontkit and local fonts measured Hebrew `שלום עולם` position advances of 4,597 versus glyph widths of 4,607, with one nonzero offset, and Latin `AV İstanbul` advances of 5,308 versus 5,348. Arabic `السَّلَامُ عَلَيْكُمْ` threw `TypeError: Cannot read properties of null (reading 'xCoordinate')` in that isolated layout call. Prior results, verified SRI, source citations and the original command are retained in `/tmp/browserpdf-phase3-font-model-readonly-20261019/report.json` and `README.txt`; saving those artifacts did not rerun the probe. These are future feasibility questions, **not app/browser failures, a support verdict or saved-PDF acceptance**. Recheck the pinned public documentation and verified post-annotation HEAD before choosing a layout approach; require actual saved logical text and independent visible Arabic/Hebrew/diacritic/mixed-bidi evidence.

The proposed shared logical model should retain paragraph/run direction, requested run styles, list identity/level/start/restart, table cells, owned image references and page/source provenance. Markdown interprets syntax into this model; DOCX supplements bounded OOXML; PDF extraction enters as literal text. DOM preview, PDF layout and DOCX generation consume the same validated model. Existing proposed byte/ZIP/asset bounds still apply; finite paragraph, run, layout-fragment and page counters must be agreed before caller lock. This preflight does not approve a new API, dependency or typography claim.

## Phase 3 — OCR and spreadsheet correction

**How this serves the primary goal:** a scan becomes inspectable searchable text, and spreadsheet conversions show and preserve the cells and columns the person intends to save.

Standalone OCR must use actual rotated/CropBox/UserUnit page geometry, supported Unicode fonts/shaping and bounded owned recognition. Existing language choices cannot remain silently selectable when their recognized text cannot be exported: supply real script support or a precise unsupported-language/font state before processing. Expose per-page recognized text, confidence, correction, rotation, retry and cancellation. User corrections are the saved searchable layer; source pixels stay unchanged when that is the promised path. Preserve one clear searchability fact through later structure-preserving compression. Typed Arabic/Hebrew signatures and mixed-script fallback remain a shared-font acceptance item; automatic italic selection must not block otherwise usable regular fonts without a supported choice.

Spreadsheet routes provide an editable bounded grid, page/table or sheet tabs, real column-width correction and meaningful print preview. Excel-to-PDF consumes all selected sheets and their widths, wraps long Unicode cells without clipping/truncation/question-mark substitution and gives explicit paper/margin settings. PDF-to-Excel rejects empty extraction, offers OCR for scans, exposes inferred rows/columns for correction and exports the actual edited workbook. Preserve source page references and precise inference limits; do not report a blank workbook as success. Request shared text/OCR/font changes from the document owner rather than editing shared files concurrently.

Verify actual reopened XLSX cells/widths/sheet names and actual PDF text/pages/positions after grid edits. Own fixtures cover two sheets, unequal widths, 92 rows, a 625-character Unicode/long-token cell with tail marker, a last-row marker, Greek/Cyrillic and blank scans. OCR covers image-only four rotations, nonzero CropBox/UserUnit, corrected Unicode and unchanged visible source pixels, selected-page retry, confidence/source state and actual cancellation of rendering/Tesseract.

## Narrow shared APIs

- `readExternalPdfFile(file, {maxBytes=80 MiB, maxPages=5000, signal})` validates an additional local PDF without changing canonical intake generation, result, session or identity. It returns owned bytes and `{baseName,name,pageCount}`. Explicit page limits up to 10,000 are accepted. The caller owns its batch totals, cancellation generation and UI. PDF.js tasks are destroyed on success, rejection and abort. PDF-lib parsing has checks before and after its uncancellable await.
- `reviewResult(bytes,name,{onAdopt(snapshot,artifact)})` provides a synchronous notification only after explicit current-generation adoption. The artifact is an owned copy. Consumers synchronously mark any subsequent hydration busy and own async cancellation/errors; the callback is not awaited.
- `reviewResult(bytes,name,{allowAdopt:false})` hides adoption when the adapter has already published the candidate as current. Download/review remain available.
- `readPdfFile(file,{validate:true,maxPages})` rejects a page-count overflow before replacing the canonical task. `adopt()` now creates a task identity when explicitly choosing the first result into an empty session; repeated same-artifact adoption and continuation retain that task/revision.
- `getWorkspaceInput()` reports the editable-scene boundary for form-only or flatten-only pending edits as well as objects. Review wording describes including pending edits and restoring the preceding editable state with Undo; it does not claim interactive fields necessarily flatten.

New shell/result/intake/style copy uses `t(key,fallback)`. New `workspace.*` keys in `object-shell.js`, the updated result UI and intake/queue/style states need the central 22-locale migration. Existing legacy field/signature error strings remain migration debt; this checkpoint does not rewrite locale dictionaries.
